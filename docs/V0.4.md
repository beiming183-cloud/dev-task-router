# V0.4 — OpenAI Plugin / Skill 化

V0.4 把项目方向从“未来做 VS Code 插件”纠正为“先做 ChatGPT / Codex 可用的轻量 Plugin”。

## 目标

让“项目拆解器”成为一个 Skill-first Plugin：用户给出开发目标后，插件负责拆任务、判难度、推荐模型档位、定义验收，并在任务失败时把失败视为原难度估计偏低的证据。

## 核心原则

```text
第一次：任务难度 → 对应模型档位
失败后：重新估计难度 → 上调一个档位
```

不是：

```text
所有任务都从弱模型开始试
```

而是：

```text
LOW task    → LOW
MEDIUM task → MEDIUM
HIGH task   → HIGH

LOW failure    → MEDIUM
MEDIUM failure → HIGH
HIGH failure   → HIGH retry / BLOCKED
```

基础设施、权限、凭据、限流、网络、工具不可用等失败不算任务难度判断错误，因此不应自动升级模型。

## Plugin 结构

```text
.agents/
  plugins/
    marketplace.json

plugins/
  dev-task-router/
    .codex-plugin/
      plugin.json
    README.md
    skills/
      index/
        SKILL.md
      decompose-project/
        SKILL.md
      classify-task/
        SKILL.md
      create-handoff/
        SKILL.md
```

当前采用 Skill-only 方案，因此 V0.4 不包含：

- `.app.json`
- `.mcp.json`
- 自建服务器
- 数据库
- VS Code Extension

这保证插件保持轻量，并避免因为 MCP server 被限制到特定桌面表面。

## 各 Skill 职责

### index

统一定义：

- `NONE / LOW / MEDIUM / HIGH` 难度语义；
- 分类因素；
- 失败后的 upward reclassification；
- verification；
- handoff 最小上下文规则。

### decompose-project

把一个开发目标转换成：

```text
Project → Stage → Step → Task
```

每个 Task 都给出：

- difficulty；
- 分类理由；
- acceptance criteria；
- handoff 边界；
- retry / escalation 配置。

### classify-task

用于单独审核某个 Task 的难度，以及判断当前分配是否过高或过低。

### create-handoff

只保留下一模型真正需要的：

- 当前任务；
- 难度和 route；
- 相关文件；
- 不能破坏的约束；
- 已验证事实；
- 失败证据；
- 下一动作。

## 与 Python Core 的关系

V0.1–V0.3 的 Python Core 保留，作为：

- 路由语义的可执行参考；
- 后续接外部执行器时的基础；
- 状态、Checker、Reviewer、Retry 的测试平台。

但项目的主要产品入口从 V0.4 开始改为 Plugin / Skill，而不是 VS Code UI。

## 当前限制

Skill-only Plugin 可以定义工作流和模型档位，但不能假装自己已经改变 ChatGPT 当前模型。真正自动切换或调用不同模型，需要产品原生支持或后续执行层。

V0.4 先把最重要的“拆解 + 难度分类 + 失败重分类 + handoff”做正确。
