# V0.8 — 本地同会话自动执行闭环

V0.8 从 V0.7 的 Same-Conversation Foundation 继续：

```text
V0.7
Task Context Pack
+ requested profile
+ local exact mode switch contract

        ↓

V0.8
Task Ready
→ Context Pack
→ requested profile
→ actual-profile gate
→ current canonical conversation
→ Checker / workflow state
```

当前 V0.8 第一阶段只实现**发送前执行契约和硬门禁**。真实 ChatGPT conversation-send backend 尚未完成，因此不会声称已经自动修改代码或完成 Task。

---

## 1. LocalExecutionEnvelope

`LocalConversationOrchestrator.prepare()` 把下一个 unresolved Task 变成：

```text
LocalExecutionEnvelope
├─ task / stage / step
├─ predicted effective difficulty
├─ Task Context Pack
├─ requested profile
└─ deterministic flag
```

Preparation 是只读步骤：

- 不增加 `attempts`；
- 不修改 Task status；
- 不触发 ChatGPT UI；
- 不把 Task 标成 RUNNING/PASSED。

Retry preview 使用现有 `level_for_attempt` 计算下一次真正执行应该使用的 Difficulty，但只有真正 Task 执行才消耗 retry。

---

## 2. LocalExecutionGate

发送给当前 ChatGPT conversation 之前必须经过 gate。

硬阻塞状态：

```text
DETERMINISTIC
STALE_CONTEXT
ROUTE_UNRESOLVED
MODE_SWITCH_UNAVAILABLE
MODE_SWITCH
PROFILE_MISMATCH
```

### DETERMINISTIC

真正的 `NONE` Task 不应进入 ChatGPT conversation，而应交给确定性 executor。

`NONE` 的定义不是“名字叫 test/build”，而是例如：

```text
kind=test/build
+ 已知 command
+ 无模型 reasoning prompt
```

带分析/实现 prompt 的 test-like Task 仍需分类，不会被强制 NONE。

### STALE_CONTEXT

如果 rolling context 的 commit anchor 已落后于当前 RepositoryContext：

```text
context.last_commit != repo.commit
```

先刷新 commit-sensitive evidence，再允许执行。

### MODE_SWITCH / PROFILE_MISMATCH

对于模型 Task：

```text
requested = sol/high
```

只有以下条件都成立才开 gate：

```text
verified == true
actual_family == requested_family
actual_effort == requested_effort
```

单纯“UI 动作执行过”不算成功。

---

## 3. Infrastructure failure 不消耗模型 retry

V0.8 明确把 preparation / context / mode switch 看作执行基础设施。

因此：

```text
selector 找不到
ChatGPT 未打开
mode switch 未验证
actual profile 不匹配
context stale
route 未配置
```

都不会：

```text
attempts += 1
LOW → MEDIUM
MEDIUM → HIGH
```

只有真正发送到模型之后发生的 reasoning / implementation / check / review failure 才能作为 Difficulty promotion 证据。

## 4. ConversationBackend contract

新增协议：

```python
class ConversationBackend(Protocol):
    def dispatch(self, envelope: LocalExecutionEnvelope) -> ConversationDispatchResult:
        ...
```

当前提供：

```text
DryRunConversationBackend
```

它永远不会假装发送成功，只用于证明执行契约。

测试用 fake backend 可以验证：只有 gate 通过后 `dispatch()` 才会被调用。

真实 Windows ChatGPT conversation backend 将作为 V0.8 后续 Step 单独实现和真机验证。

## 5. CLI

新增：

```text
autodev-local prepare --json
```

只准备下一个 Task：

```text
Context Pack
Difficulty
requested profile
stale status
```

不会操作 ChatGPT UI。

检查 gate：

```text
autodev-local gate --dry-run --json
```

Dry-run 会明确显示 switch 未验证，因此 `allowed_to_dispatch=false`，但作为检查命令退出成功。

真机校准完成后可运行：

```text
autodev-local gate --switch --json
```

真实 switch gate 采用 fail-closed：未验证则非零退出。

## 6. 当前完成边界

第一阶段自动回归覆盖：

- Context Pack → execution envelope；
- effective Difficulty / requested profile；
- prepare 不修改 attempts/status；
- missing switch backend 阻塞；
- unverified switch 阻塞；
- verified 但 profile mismatch 阻塞；
- stale context 在 mode switch 前阻塞；
- verified profile 才允许 conversation backend 被调用；
- conversation backend 接受 != Task PASSED；
- genuine deterministic NONE 不进入 chat；
- test-like reasoning Task 不会被错误强制 NONE；
- `autodev-local prepare/gate --dry-run` CLI。

真实执行仍缺：

```text
Windows current-conversation composer detection
→ safely insert Task Context Pack
→ duplicate-send protection
→ submit
→ detect response completion
→ collect result
→ hand result to Checker / state machine
```

这些是 V0.8 下一 Step。
