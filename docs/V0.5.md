# V0.5 — Smart Difficulty Classifier + Surface Routing

V0.5 separates two decisions that were previously mixed together:

```text
Task content
  ↓
Difficulty classifier
  ↓
NONE / LOW / MEDIUM / HIGH
  ↓
Execution surface
  ↓
surface-specific model / effort
```

## Why

The same HIGH task may be executed differently in Chat, Codex, or Work. Therefore task difficulty must not be encoded as a concrete model name.

## Content-level classifier

The Python reference core now has an explainable deterministic classifier. It does not call an external API.

Signals include:

- task kind baseline;
- architecture/core-semantics wording;
- state/lifecycle/concurrency complexity;
- security/auth/migration/release/compatibility risk;
- cross-module/public-interface impact;
- ambiguity/design burden;
- verification burden;
- localized/mechanical wording.

Output:

```text
level
score
confidence
reason
factors
traits
```

This gives V0.5 a testable baseline before an LLM classifier is connected later.

## Surface routing

`.autodev/surfaces.yaml` is created by `autodev init`.

Current default shape:

```yaml
default_surface: chat
surfaces:
  chat:
    strategy: fixed
    routes:
      LOW:    {family: sol, effort: low}
      MEDIUM: {family: sol, effort: medium}
      HIGH:   {family: sol, effort: high}

  codex:
    strategy: pool
    families: [lunar, terra, sol, astra]
    efforts: [low, medium, high]
    routes: {}

  work:
    strategy: pool
    families: [lunar, terra, sol, astra]
    efforts: [low, medium, high]
    routes: {}
```

Chat is currently a resolved mapping.

Codex and Work deliberately remain a configurable pool. V0.5 does **not** assume an ordering such as `lunar < terra < sol < astra`. When no route is configured, the result is `unresolved` and shows the candidate pool.

## Failure policy

The Plugin plan format uses:

```yaml
escalate_after: 1
```

for model-executed tasks.

Meaning:

```text
LOW failure    → MEDIUM
MEDIUM failure → HIGH
HIGH failure   → HIGH retry / BLOCKED
```

The first attempt is still difficulty-matched; this is not weak-first routing.

Infrastructure failures should not be treated as evidence that the task is harder.

## Plugin skills

V0.5 has five main skills:

- `index` — shared rules;
- `decompose-project` — project → stage → step → task;
- `classify-task` — content-level difficulty + confidence + traits;
- `route-model` — surface-specific model mapping;
- `create-handoff` — minimal next-task context.

## Current limits

- no external model API is required;
- Codex/Work family ranking is not guessed;
- no automatic ChatGPT model-selector click/switch is claimed;
- the deterministic classifier is a baseline, not the final adaptive classifier;
- repository-aware features remain V0.6.
