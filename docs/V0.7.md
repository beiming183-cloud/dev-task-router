# V0.7 — 同会话执行：Local Exact Switch + Rolling Context

V0.7 解决两个互相绑定的问题：

```text
1. 不换聊天窗口，按 Task 难度原地切换 ChatGPT 推理档位
2. 不依赖无限聊天历史，用滚动项目上下文保持长项目稳定
```

核心原则：

```text
Task decomposition != conversation decomposition
```

复杂项目默认保持一个 canonical conversation。Task 可以是 LOW / MEDIUM / HIGH，但 conversation 不因此拆开。

---

## A. Local Exact Mode Switch

### 核心接口

```python
ModeSwitchController.switch_level(level, surface="chat")
```

输出 `SwitchResult`：

```text
requested profile
actual family
actual effort
verified
backend
changed
message
```

`requested` 与 `actual` 必须分开。Router 想要 HIGH 不代表界面已经成功切到 HIGH。

### Backend

`DryRunModeSwitchBackend` 用于 CI 和路由验证，不触碰本地 UI。

`WindowsUIAModeSwitchBackend` 用于 Windows 真机 exact switch：

- 使用 `pywinauto` UIA backend；
- 不使用固定鼠标坐标；
- 通过 window title / accessibility text / automation id 等信息寻找控件；
- selector、family、effort、verify labels 全部配置化；
- UI 动作后必须重新读取 UI 做验证；
- 无法验证则失败，不继续在错误 profile 下执行任务。

### 配置

`autodev init` 生成：

```text
.autodev/local-switch.yaml
```

默认禁用，并且 selector label 留空。不同 ChatGPT build、语言和客户端可能暴露不同 accessibility label，必须先 probe，不猜控件。

### 安装与 Probe

Windows：

```powershell
pip install -e ".[local]"
autodev-mode probe --json
```

Probe 只读取当前可见 ChatGPT 窗口的 UIA 控件，不点击任何东西。

校准后再执行：

```powershell
autodev-mode switch LOW --surface chat --json
autodev-mode switch MEDIUM --surface chat --json
autodev-mode switch HIGH --surface chat --json
```

真机成功的最低条件：

```json
{
  "verified": true
}
```

### Mode-switch failure

ChatGPT 未打开、selector 找不到、UI label 改变、UIA 权限失败、依赖未安装、切换后无法验证，都属于执行基础设施失败。

它们不能触发 Difficulty promotion：

```text
LOW -> MEDIUM
MEDIUM -> HIGH
```

后续统一记录为 `MODE_SWITCH` 类失败。

## B. Rolling Project Context

同一个 conversation 也不是无限上下文窗口。V0.7 新增：

```text
.autodev/context.yaml
```

它只保存应该跨多个 Task 长期存在的信息：

```text
project goal
still-valid decisions
protected constraints
stage notes
task-specific unresolved notes
last commit anchor
```

它不是聊天记录副本，不保存整段 assistant 回复，也不保存整个仓库摘要。

### 数据结构

Python Core 新增：

```text
RollingProjectContext
ContextBudget
TaskContextPack
ContextPackBuilder
```

`RollingProjectContext` 会对重复字符串做归一化去重，并可判断：

```text
context.last_commit != repo.commit
→ stale_context = true
```

这只表示 commit-sensitive repository facts 需要刷新，不意味着所有长期架构决策都自动失效。

### Task Context Pack

每个 Task 执行前，可以生成一个预算化 Context Pack：

```text
Project / Stage / Step / Task
Project goal
Decisions that still apply
Protected constraints
Stage context
Task-specific context
Acceptance
Recent failure evidence
Relevant repository files/facts/CI
Requested execution profile
Exact next action
Stale-context warning
```

默认预算避免上下文无限增长。超出预算时，优先保留最近、最相关的项目状态，而不是重新发送完整聊天历史。

CLI：

```powershell
autodev context
autodev context --json
autodev context --import context.yaml

autodev context-pack <task-id>
autodev context-pack <task-id> --json
```

### Handoff 改造

`handoff.md` 不再默认展开完整历史任务表。

现在优先输出：

```text
当前项目状态
↓
Next Task Context Pack
↓
最多 10 个 unresolved task 的紧凑 ledger
```

已经 PASSED 的老 Task 不反复占据 handoff。工作流全部完成时只保留最终完成 Task 的 compact route 和最终 repo anchor，以兼容审计。

## C. Same-conversation execution chain

V0.7 的目标链路变成：

```text
same canonical conversation
        ↓
read rolling context
        ↓
build next Task Context Pack
        ↓
classify LOW / MEDIUM / HIGH
        ↓
resolve requested profile
        ↓
local exact mode switch
        ↓
verify actual profile
        ↓
execute Task
        ↓
verify code/test/diff
        ↓
update rolling context only with durable information
        ↓
next Task, same conversation
```

所以 Context Pack 的目的不是鼓励换窗口，而是让**同一个长窗口**在项目持续很久以后依然有一个干净、可恢复的工作集。

## CI 能验证什么

GitHub Actions 可以验证：

- local switch config parsing；
- Surface route -> RequestedProfile；
- requested / actual 分离；
- dry-run backend contract；
- RollingProjectContext 去重；
- Context Budget；
- task-specific pack；
- stale commit detection；
- context-pack-first handoff；
- Plugin skills / manifest。

Linux CI 不能验证用户实际 Windows ChatGPT UIA 树，因此 Local Exact Switch 仍需要一次 Windows 真机校准。
