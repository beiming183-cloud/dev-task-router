# V0.7 — 本地同会话 Exact Mode Switch

V0.7 把项目重点从“仅给出模型建议”推进到“在 Windows 本地真正切换当前 ChatGPT 会话的 execution profile”。

## 为什么先做本地

项目的原始目标是：

```text
复杂项目
↓
拆成不同难度 Task
↓
简单任务少用推理
复杂任务多用推理
↓
始终保持同一个项目上下文
```

因此 V0.7 明确采用：

```text
Task decomposition != conversation decomposition
```

不通过为 LOW / MEDIUM / HIGH 分别新建多个聊天来换模型，而是保持 canonical conversation，在任务边界原地切换 profile。

## 核心接口

```python
ModeSwitchController.switch_level(level, surface="chat")
```

输出 `SwitchResult`：

```text
requested profile
actual family
aactual effort
verified
backend
changed
message
```

其中 `requested` 与 `actual` 必须分开。Router 想要 HIGH 不代表界面已经成功切到 HIGH。

## Backend

### DryRunModeSwitchBackend

用于 CI 和路由验证，不触碰本地 UI。

### WindowsUIAModeSwitchBackend

用于 Windows 真机 exact switch。

原则：

- 使用 `pywinauto` 的 UIA backend；
- 不使用固定鼠标坐标；
- 通过 window title / accessibility text / automation id 等稳定信息寻找控件；
- selector、family、effort、verify labels 全部放在配置中；
- UI 动作后必须重新读取 UI 做验证；
- 无法验证则失败，不继续在错误 profile 下执行任务。

## 配置

`autodev init` 生成：

```text
.autodev/local-switch.yaml
```

默认：

```yaml
enabled: false
backend: windows-uia
window:
  title_regex: ".*ChatGPT.*"
selector:
  open_labels: []
family_labels:
  sol: []
effort_labels:
  low: []
  medium: []
  high: []
verify_labels:
  low: []
  medium: []
  high: []
```

默认故意不提供猜测 selector。不同 ChatGPT build、语言和客户端可能暴露不同 accessibility label，必须先 probe。

## 安装本地依赖

Windows 项目目录：

```powershell
pip install -e ".[local]"
```

本地 extra 目前只增加：

```text
pywinauto>=0.6.8
```

## Probe

保持 ChatGPT 桌面端打开在要继续开发的同一个 conversation：

```powershell
autodev-mode probe --json
```

它读取当前可见 ChatGPT 窗口的 UIA 控件，不点击任何东西。

根据输出确定：

- 打开模型/推理选择器的控件；
- Sol/model family 控件（如果当前 UI 需要单独选择）；
- Low / Medium / High 的菜单项；
- 切换完成后用于确认当前档位的可见 label。

然后填入 `.autodev/local-switch.yaml` 并设置：

```yaml
enabled: true
```

## Dry run

不碰 UI，先检查路由：

```powershell
autodev-mode switch HIGH --surface chat --dry-run --json
```

当前 Chat route 应解析为：

```text
LOW    -> sol / low
MEDIUM -> sol / medium
HIGH   -> sol / high
```

## 真机验收

依次运行：

```powershell
autodev-mode switch LOW --surface chat --json
autodev-mode switch MEDIUM --surface chat --json
autodev-mode switch HIGH --surface chat --json
```

每次成功的最低条件：

```json
{
  "verified": true
}
```

如果 UI 动作发生但不能确认实际状态，返回失败。

## Failure semantics

以下都属于本地执行基础设施失败：

- ChatGPT 没打开；
- selector 找不到；
- accessibility label 已变化；
- Windows UI Automation 权限失败；
- `pywinauto` 未安装；
- requested profile 切换后无法验证。

它们不能触发：

```text
LOW -> MEDIUM
MEDIUM -> HIGH
```

因为这并不证明 Task 更难。

后续 workflow 中统一记录为 `MODE_SWITCH` 类失败。

## CI 能验证什么

Linux GitHub Actions 可以验证：

- 配置解析；
- Surface route -> RequestedProfile；
- unresolved pool 不猜模型；
- requested / actual 分离；
- dry-run；
- verified backend contract；
- Skill/manifest package。

但 CI 不能验证用户实际 ChatGPT 桌面版的 UI 树，因此 V0.7 合并前必须增加一次 Windows 真机校准与 LOW/MEDIUM/HIGH 三档验收。
