# V0.1 Core

V0.1 的目标不是接入真正的多模型，而是先验证最小工作流闭环：

```text
plan.yaml
   ↓
读取并校验任务
   ↓
单执行器运行命令
   ↓
执行 checks
   ↓
持久化 state.json
   ↓
继续下一任务 / FAILED / PASSED
```

## 已实现

- `.autodev/project.yaml`
- `.autodev/plan.yaml`
- `.autodev/state.json`
- `autodev init`
- `autodev plan`
- `autodev start`
- `autodev pause`
- `autodev resume`
- `autodev status`
- `READY / RUNNING / PAUSED / FAILED / PASSED` 工作流状态
- `PENDING / RUNNING / FAILED / PASSED` 任务状态
- 每个任务记录 attempts、时间和 last_error
- argv 形式命令执行器，不使用 `shell=True`
- task checks
- 计划与状态任务集合一致性检查
- 仓库自身的 GitHub Actions pytest CI

## V0.1 有意不做

- 真正的 LLM / Coding Agent 接入
- LOW / MEDIUM / HIGH 实际模型路由
- 自动重试和模型升级
- Reviewer
- Git diff / commit 自动验证
- VS Code UI
- 把 GitHub Actions 作为用户任务的远程执行器

这些能力按 ROADMAP 在 V0.2+ 增加。

## 本地试用

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -e .

autodev init --name demo
autodev plan
autodev start
autodev status
```

默认 `plan.yaml` 只有一个无副作用的 smoke task。之后可手动把任务替换成 argv 命令，例如：

```yaml
version: 1
project: demo
tasks:
  - id: tests
    title: Run tests
    model: NONE
    command: ["python", "-m", "pytest", "-q"]
    checks: []
```

## 当前限制

`pause` 是“在下一个任务开始前暂停”。正在运行的单个外部命令在 V0.1 不会被强制中止。

如果任务 FAILED，V0.1 不自动 retry；这是为了避免第一版在状态语义尚未稳定前隐藏失败。自动 retry / escalation 放到 V0.3。
