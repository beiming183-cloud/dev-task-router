# V0.2 — Task Routing Core

V0.2 在 V0.1 的可靠状态机之上加入真正的“任务分层 + 模型路由”基础设施。

## 已实现

- `Project → Stage → Step → Task` 层级计划；
- 继续兼容 V0.1 的 flat `tasks:` 计划；
- `ModelLevel = NONE / LOW / MEDIUM / HIGH`；
- `TaskRole = PLANNER / EXECUTOR`；
- `.autodev/models.yaml`；
- 基于 `task.kind` 的 RuleRouter；
- Task 显式 `level` 可覆盖默认规则；
- Model Profile：`provider / model / executor`；
- Executor Protocol 与 Executor Registry；
- 本地 `command` Executor；
- 通用 `agent-cli` Executor，可把不同模型路由到不同外部 Agent CLI；
- `.autodev/handoff.md` 自动生成；
- `.autodev/usage.jsonl` 初步执行记录；
- state 记录 stage / step / role / kind / 实际 route；
- V0.1 项目缺失 `models.yaml` 时自动补默认配置。

## 默认路由

```text
repo_search / docs / handoff / simple_edit → LOW
normal_code / normal_debug                → MEDIUM
architecture / planning / complex_code    → HIGH
hard_debug / review                       → HIGH
test / build                              → NONE
未知 kind                                 → MEDIUM
```

Task 可以显式指定：

```yaml
level: HIGH
```

显式 level 优先于 RuleRouter。

## V2 plan.yaml 示例

```yaml
version: 2
project: demo
stages:
  - id: architecture
    title: Architecture
    steps:
      - id: inspect
        title: Inspect current design
        tasks:
          - id: plan-change
            title: Plan the change
            role: PLANNER
            kind: architecture
            prompt: Review the project and produce the implementation plan.

  - id: implementation
    title: Implementation
    steps:
      - id: small-fixes
        tasks:
          - id: docs-fix
            title: Update docs
            role: EXECUTOR
            kind: docs
            prompt: Update the relevant documentation.
```

## models.yaml

默认配置保持安全：四个等级都使用本地 `command` executor，不会在用户没有配置时突然启动外部 AI。

要接入现有 Coding Agent，可把某个等级切到 `agent-cli`：

```yaml
profiles:
  NONE:
    provider: local
    model: none
    executor: command

  LOW:
    provider: your-provider
    model: your-cheap-model
    executor: agent-cli
    command:
      - your-agent-cli
      - --model
      - "{model}"
      - --prompt
      - "{prompt}"

  MEDIUM:
    provider: local
    model: medium
    executor: command

  HIGH:
    provider: local
    model: high
    executor: command
```

`agent-cli` command template支持以下占位符：

- `{model}`
- `{provider}`
- `{prompt}`
- `{task_id}`
- `{role}`

命令以 argv 方式执行，不使用 `shell=True`。

不同 CLI 的真实参数不同，因此 V0.2 不把 Codex / Claude / Gemini 的具体参数硬编码进 Core；后续可以增加专门 Adapter。

## Handoff

每次状态变化后更新：

```text
.autodev/handoff.md
```

内容包括：

- 当前 Workflow 状态；
- 当前 Task；
- 完成数量；
- 下一个未完成任务；
- 每个 Task 的 Stage / Step / Role；
- 实际使用的 Level / Provider / Model / Executor。

目的是让下一模型接手时优先读取 Handoff 和相关代码，而不是重新读取整段聊天历史。

## Usage

每个实际完成或失败的 Task 写一条：

```text
.autodev/usage.jsonl
```

V0.2 已记录：

- task_id
- level
- provider
- model
- executor
- status
- returncode

Token 字段暂时保留为 `null`；真实 Token 统计等 Provider Adapter 能返回 usage 后再接入。

## CLI

V0.2 新增：

```text
autodev models
autodev handoff
```

`autodev plan` 现在会直接显示每个 Task 最终路由到哪个模型 Profile 和 Executor。

## 当前边界

V0.2 解决“任务应该交给谁”和“如何调用不同执行器”。它还不负责：

- 自动 Retry；
- 失败后 MEDIUM → HIGH 升级；
- 独立 Reviewer；
- Git diff / Commit 验证；
- Token 成本统计；
- 自动复杂度分类。

这些进入 V0.3 及后续版本。
