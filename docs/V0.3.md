# V0.3 — Verification / Retry / Reviewer

V0.3 的目标是把 V0.2 的“模型路由”升级成一个有失败闭环的执行流程：

```text
Executor
   ↓
Checker
   ↓
失败？ ── yes ──→ Retry
   │                ↓
   │             仍失败
   │                ↓
   │             Escalate
   │                ↓
   │             BLOCKED
   ↓ no
Reviewer（可选）
   ↓
PASS
```

## 新增能力

- `max_attempts`：单 Task 最大自动尝试次数；
- `escalate_after`：从第几次失败后开始升级模型；
- 默认升级链：`LOW → MEDIUM → HIGH`；
- `BLOCKED` Workflow / Task 状态；
- `acceptance`：给独立 Reviewer 的验收条件；
- `review: true`：启用独立 Reviewer；
- `review_level`：Reviewer 使用的模型等级，默认 `HIGH`；
- `require_diff: true`：要求任务产生真实 Git 工作区变化；
- `failures[]`：保存每次失败类型、模型路由、时间和错误；
- `route_history[]`：记录每次尝试实际用了什么等级和模型；
- `autodev retry <task>`：人工检查后重开一个新的重试周期。

## Retry / Escalation

例：

```yaml
- id: implement-parser
  title: Implement parser
  kind: normal_code
  max_attempts: 3
  escalate_after: 2
  prompt: Implement the parser and keep existing behavior compatible.
```

如果 `normal_code` 默认映射为 `MEDIUM`，执行路线为：

```text
attempt 1 → MEDIUM
attempt 2 → MEDIUM
attempt 3 → HIGH
```

当 `max_attempts > 1` 且全部失败后，Task 与 Workflow 进入：

```text
BLOCKED
```

不会静默无限重试。

为了兼容 V0.1/V0.2，未配置 `max_attempts` 的旧任务默认仍然只有一次尝试；单次失败仍表现为 `FAILED`。

## Checker

Checker 是确定性 Gate，不依赖模型自己说“完成”。

现阶段支持：

1. Task `checks` 命令；
2. 可选 Git diff / working-tree change Gate。

例：

```yaml
- id: change-code
  title: Change code
  kind: normal_code
  require_diff: true
  max_attempts: 2
  prompt: Fix the bug.
  checks:
    - ["python", "-m", "pytest", "-q"]
```

如果测试命令失败，失败类型记录为 `CHECK`。

如果启用了 `require_diff` 但任务执行前后 Git 工作区状态完全相同，失败类型记录为 `DIFF`。

## Independent Reviewer

Reviewer 与任务 Executor 使用不同角色：

```text
EXECUTOR
   ↓
CHECKER
   ↓
REVIEWER
```

配置示例：

```yaml
- id: cursor-selection
  title: Implement semantic selection
  kind: complex_code
  prompt: Implement semantic selection without changing delete/history behavior.
  review: true
  review_level: HIGH
  acceptance:
    - Existing delete behavior is unchanged
    - Existing history behavior is unchanged
    - New semantic-selection tests pass
```

Reviewer 收到的是：

- 原始任务；
- acceptance criteria；
- Checker evidence。

Reviewer 必须以最后一个非空行的 `PASS` 或 `FAIL` 给出机器可解析结论。

若 Reviewer 输出 `FAIL`、运行失败、输出为空或格式无法解析，任务不会进入 PASSED，而是走 Retry / Escalation。

> `review: true` 时，对应 `review_level` 的 Model Profile 应配置为支持 prompt 的 Executor（例如 `agent-cli`）。默认 `command` Profile 不会假装具备 AI Review 能力。

## Manual Retry

任务进入 `FAILED` 或 `BLOCKED` 后：

```bash
autodev retry <task-id>
```

只重置当前 Task 的本轮尝试预算，保留历史：

- `failures[]`
- `route_history[]`
- `retry_cycles`

然后：

```bash
autodev start
```

也可以：

```bash
autodev retry <task-id> --run
```

立即重新运行。

## 状态语义

Workflow：

```text
READY
RUNNING
PAUSED
FAILED
BLOCKED
PASSED
```

Task：

```text
PENDING
RUNNING
FAILED
BLOCKED
PASSED
```

`FAILED` 用于没有自动重试预算的失败任务；`BLOCKED` 表示配置了自动重试，但预算已经耗尽，需要人工介入。

## V0.3 暂不做

- 自动解析真实模型 Token 用量；
- 自动生成/修复 Git commit；
- Reviewer 读取完整 Git diff 的智能上下文裁剪；
- 并行 Agent；
- VS Code UI；
- GitHub Actions 作为用户任务 Worker。

这些能力继续按 ROADMAP 推进。
